# Blogging Workflow

## Purpose

Support continuous publication of useful, coherent articles while preserving voice, themes, factual quality, prior arguments, audience learning and long-term editorial direction.

## Strategic layer

The Workflow Strategist owns `WORKFLOW_STRATEGIC` blogging memory: themes, audience assumptions, voice/style decisions, published topics, arguments already made, editorial principles, experiments, distribution observations, audience response and lessons.

The Strategist determines HOW the blog should develop and which publishing strategy/flow best serves the current editorial objective. WHY blogging matters relative to other goals, WHEN it deserves human attention, and how it competes with other workflows belong to the Global Governor.

## Strategies

Blogging can use substantially different strategies. Examples live under [`strategies/`](strategies/):

- [`thought-leadership.md`](strategies/thought-leadership.md)
- [`seo-content.md`](strategies/seo-content.md)

The Strategist may select, combine, adapt or replace strategies based on evidence.

## Candidate execution roles

Possible ephemeral `SESSION` roles include Idea Researcher, Researcher, Writer, Fact Reviewer, Editor and Publishing/Distribution Assistant.

## Events and adaptive flow

Meaningful events may include an idea/observation appearing, topic selection, research completion, draft creation, review findings, publication, audience response, search/distribution evidence and follow-up opportunities.

A typical flow may resemble:

`ideas/events -> strategic selection -> research -> draft -> review/edit -> publish -> observe evidence -> learn -> future selection`

This is illustrative rather than mandatory. Strategy determines the actual flow.

## Memory boundary

Published articles and source materials remain authoritative artifacts. Workflow memory should make prior work easy to retrieve and reason about without replacing the originals. Execution agents have no permanent personal memory; durable editorial lessons flow back to the Strategist.

## Runtime boundary

The workflow is independent of a particular CMS, publishing platform, analytics provider, model or harness. Runtime/profile configuration supplies concrete publishing destinations, credentials, analytics sources, models and tools.
