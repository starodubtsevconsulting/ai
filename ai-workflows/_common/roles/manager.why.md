# Why Manager?

![Manager role visual](img/manager.png)

Reasoning about work and keeping track of work are not quite the same job.

A Designer Reviewer may be better equipped to understand a difficult change, decompose it and propose a credible estimate. Somebody still needs to turn that reasoning into tracked tickets, assignments, priorities supplied by the right decision-maker, and an appropriately staffed team.

Manager owns that coordination layer.

It does not need to pretend to be the smartest agent in the workflow. In fact, when an estimate arrives as an unsupported number, Manager can send it back and ask the stronger reasoning agent for decomposition and evidence. Once the work is sufficiently clear, Manager can record and coordinate it.

Manager also deals with capacity. If a Coder is exhausted or another worker is needed, Manager can replace or add an agent and update the team's runtime roster correctly.

The role exists to keep operational coordination explicit instead of scattering ticket administration and staffing across whichever agent happens to be available.
